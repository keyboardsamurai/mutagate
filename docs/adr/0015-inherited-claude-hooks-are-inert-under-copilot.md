# ADR-0015: Inherited Claude hooks are inert under Copilot
Status: accepted 2026-11-08
Concern: GitHub Copilot CLI also runs the hooks in `.claude/settings.json`. Copilot CLI 1.0.104 runs all of them except `TaskCompleted`, runs the `--mutate` hook synchronously and sets `CLAUDE_PROJECT_DIR`. It does not block on exit 2 from `Stop` and does not show plain-text output. Thus, under Copilot, edits wait for mutation runs, `Stop` spends gate rounds without a block, and teammates who did not install mutagate for Copilot get these runs.
Decision: A hook call whose payload has a top-level `timestamp` is an inherited hook call from Copilot. mutagate makes this decision before it detects, writes state, locks or gates. An inherited hook call does not detect, write state, lock, start a worker, register a test, gate or record its payload. It exits 0 and writes nothing to stdout, and `Stop` and `SubagentStop` do not change `blocks`. Only `SessionStart` writes one JSON object, `{"additionalContext": "mutagate inactive under Copilot: …"}`, and only when no native Copilot hook file exists: project `.github/hooks/mutagate.json`, user `$COPILOT_HOME/hooks/mutagate.json`, else `~/.copilot/hooks/mutagate.json`. With `MUTAGATE_TRACE=1`, the trace records the harness `copilot` and the decision `inherited`. The environment does not change the decision: `CLAUDE_PROJECT_DIR` and `CLAUDE_PLUGIN_*` do not make an inherited hook call `claude`, and a Copilot environment variable does not make a call inherited.
Rationale: An active mutagate under Copilot gates teammates who did not choose it (#35 D3). Each recorded Copilot CLI event has `timestamp`. The 400 recorded Claude Code payloads and the 397 recorded Codex, OpenCode and Pi payloads do not have it. The Copilot environment variables (`COPILOT_CLI`) also go to a Claude Code that starts from a Copilot shell, so they cannot identify the caller.
Alternatives: A payload shape for each event (`tool_result`, `stop_reason`) and a Copilot environment variable as fallback (#35 D4). One key is sufficient, and the fallback makes such a Claude Code inert. Rejected. Run the inherited hooks as Claude hooks. The gate cannot block and edits wait, see Concern. Rejected.
Consequences: Under Copilot, mutagate does not gate and the waiver guard is off until the native Copilot install (#35, 0.9.2). The check is in the runtime, so a skill update without `install` makes an old Claude install inert under Copilot. The native Copilot install must tag its hook commands, because its payloads also have `timestamp`. Copilot in VS Code 1.145 did not run these hooks. The VS Code Claude session target sends Claude payloads without `timestamp`, so it stays `claude`. The recorded payloads are in `test/payloads/copilot/cli/` and `test/payloads/copilot/vscode-claude/`.
