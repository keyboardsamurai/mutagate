# ADR-0020: Copilot payloads and sessions
Status: accepted 2026-11-09
Concern: Native GitHub Copilot hooks (`.github/hooks/*.json`) send camelCase payloads. The payloads have no `hook_event_name` and no harness field. A subagent call has a `sessionId` that is the subagent's own `agentId`, not the root session id. The hook environment has `CLAUDE_PROJECT_DIR` and no `COPILOT_AGENT_SESSION_ID`. The root agent's shell has `COPILOT_AGENT_SESSION_ID`, equal to the hook `sessionId` (Copilot CLI 1.0.107, `test/payloads/copilot/cli-native/`).
Decision: Each native hook command gives the internal event and `--harness copilot` (a native hook call). The argument event and the tag win: a native hook call has the harness `copilot` and is not inherited, whatever its payload `timestamp` and its `CLAUDE_*` environment (ADR-0015). `scripts/copilot.cjs` normalizes the payload after `main` records the raw payload. `sessionId` becomes `session_id`. The tools `create`, `edit` and `str_replace_editor`, `apply_patch`, `bash` and `powershell` become `Write`, `Edit`, `apply_patch` and `Bash`. The `toolArgs` keys `path`, `file_text`, `old_str` and `new_str` become `file_path`, `content`, `old_string` and `new_string`. Other tools, for example `view`, get an empty tool input and thus name no file. The raw patch text of `apply_patch` becomes `{command}`, with each file path resolved against the payload `cwd`. mutagate does not subscribe `postToolUseFailure`. The `SubagentStart` hook call records `agentId → parentAgentId` in the data dir: one file for each agent, written atomically, with no state lock. A call with `agentId` follows `parentAgentId` through these records until an id has no record. That id is the root session id: at depth 1 `parentAgentId` is the root session id, so depth 1 needs no record. A call without `parentAgentId`, or with a loop, keeps its own session, and the trace marks it `chain: "unresolved"`. The session id is the first present of: payload `sessionId` (through the chain), `MUTAGATE_HOOK_SESSION`, `CODEX_THREAD_ID`, `CLAUDE_CODE_SESSION_ID`, `COPILOT_AGENT_SESSION_ID`, `MUTAGATE_SESSION`, then a `ppid-` fallback (ADR-0009). The repo of a native hook call is the Git top level of the payload `cwd`: the nearest dir with a `.git` entry. `CLAUDE_PROJECT_DIR`, which Copilot sets to the launch dir, does not change it. A `run`, `check`, `status` or `waive` call without `--repo` whose session id is `COPILOT_AGENT_SESSION_ID` (the root agent's shell, which starts in the launch dir) also uses the Git top level of its cwd, and `run` resolves a relative test path against the cwd, or against the Git top level when no file is at the cwd path. Outside Git, the repo is resolved as for Claude. A native hook call without `sessionId` exits 0, writes a trace row with the decision `error`, and writes no state. mutagate uses no event token and no Stop key: the edit token stays the hash of the paths and the tool input, and `toolCallId` and `timestamp` are not used.
Rationale: The tag is the only reliable mark of a native hook call: the payload `timestamp` also marks inherited calls, and Copilot sets `CLAUDE_PROJECT_DIR`. Normalization in one lazy module keeps the hook path of the other harnesses unchanged. The chain lets the root `agentStop` gate the writes of each subagent, `general-purpose` included. `COPILOT_AGENT_SESSION_ID` lets the root agent's CLI calls join the hook session. With the Git top level, a hook call from a subdirectory uses the same state as the root `agentStop`, and the root agent's CLI calls use that state also when Copilot starts below the Git top level. An empty tool input for the other tools keeps a read from making results stale if the hook matcher does not filter it (matchers have no recording). A duplicate hook file is a misconfiguration that `install` refuses; a duplicate event costs one more handler and a second, fast gate pass.
Alternatives: Each subagent has its own session, like the Claude `agent_id`, and its own `agentStop` gates it. Rejected: the maintainer chose one gate at the root `agentStop` (#35 D18). Follow `sessionId` of `subagentStart`. At depth 2 it is an internal id that no other call has. Rejected. An event token from `sessionId` and `toolCallId`, and a Stop key from `sessionId` and `timestamp`. Added only if duplicate events occur in practice (#35 D20).
Consequences: A subagent's shell has an internal `COPILOT_AGENT_SESSION_ID` that matches no hook id, so its CLI calls do not join the root session. Copilot started inside Claude Code or Codex: the CLI joins the outer session. A depth-2 write without its `subagentStart` record (for example, after a failed `subagentStart` hook) registers in the session of the parent subagent, which no `agentStop` gates. The cache prune deletes chain records after 14 days without a write. The `str_replace_editor` mapping has no recording. In the root agent's shell, `install` and `doctor` keep the cwd as the repo.
