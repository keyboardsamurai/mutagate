# ADR-0022: Harness profiles
Status: accepted 2026-11-10
Concern: The engine has about 17 harness checks in `context`, `state`, `pendingText`, `gate`, `handleHook` and `main`, with three different tests for Copilot: the `--harness copilot` tag, `c.harness === 'copilot'` and the `COPILOT_*` env. Payload shape, session and repo, output encoding, stderr and exit policy, the waiver answer and the async rerun path change with the harness. A new harness or a change for one harness touches many places in the engine. Tests of Copilot hook calls make the steps of `main` again by hand.
Decision: Each mutagate call uses one harness profile: `claude`, `codex`, `opencode`, `pi`, `copilot`, `copilotShell`, `inherited` (ADR-0015) or `unknown`. `opencode` and `pi` share one profile. `copilot` is the native call; only the `--harness copilot` tag gives it (ADR-0020). `copilotShell` is Copilot by name without the tag: the root agent shell, its workers and payload `harness`. It is Claude-shaped. One function `pick` chooses the profile in this order: the `--harness` tag, payload `timestamp` (`inherited`), `MUTAGATE_HARNESS` (workers), payload `harness`, the Copilot root agent shell (`COPILOT_AGENT_SESSION_ID` for a session command, never for a hook call), the Codex markers, the `CLAUDE_*` markers, else `unknown`. A profile starts from a Claude-shaped `base` and changes only the methods that differ: `read` (origin and normalization, or inert), `place` (repo and session id), `admit`, `write`, `stop`, `deliveries` and `survivor`. The small hooks are `ready`, `rerun` and `tags`. The data fields are `events`, `label`, `inert`, `quiet`, `waiver`, `bashWait` and `harness`. `harness` is the trace name: `copilotShell` and `inherited` set it to `copilot`. `copilotShell` also sets `bashWait`. The Copilot root agent shell gets the Git top of cwd from `place`, whatever the tag. `handleHook` returns harness-neutral intents: nothing, context, notice, a waiver confirm, block, warn, or survivors. An `admit` refusal is `error` (traced, no output). The Copilot watchdog gives warn with `deadline`. `write` changes an intent to exit code, stdout and stderr, and has no side effects. `gate` has no harness branch; the Copilot `agentStop` gives it options. The shared helpers `state` and `pendingText` read `quiet` and `bashWait`. `runHook(argv, stdin text, env)` returns `{code, stdout, stderr}`, and `deadline` when the watchdog ended the call. It gives `env` to `pick` and reads `MUTAGATE_RECORD` from it. `shell(args, payload, env)` reads the Copilot shell markers. No profile method takes `env`. `runHook` is the test surface for hook calls; `main` only does the process I/O. `scripts/harness.cjs` holds `pick`, `base` and the simple profiles and is loaded lazily. `scripts/copilot.cjs` is the Copilot profile. Neither file is hashed into `fingerprint`. `c.harness` stays the harness name in traces; an inherited call traces harness `copilot` and decision `inherited`.
Rationale: The harness rules for one harness are in one place, and the engine does not compare harness names. A test gives a raw payload and reads the encoded output, through the same steps as a real hook call. Methods on a `base` keep each simple profile small; only Copilot changes many methods. Plain code in `pick` keeps the selection order visible.
Alternatives: A data table of profile fields (`wrap`, `waiver`, `rerun`, `wakeExit`, …) that the engine reads. Rejected: most Copilot fields only rename one Copilot branch, and the selection needs a small matching language. A profile with one `serve` method around `handleHook`. Rejected: each profile then has its own switch on the event. Profile flags for the two Copilot branches in `gate`. Rejected: only the Copilot `agentStop` uses them, so they are options of that call. The `env` passed through every profile method. Not now: only `pick` and `shell` take it.
Consequences: Each hook call loads `harness.cjs` (about 1 ms). A session command in the Copilot root agent shell traces harness `copilot`. A new harness needs a profile and a branch in `pick`.
