# ADR-0017: The install stamp travels with each install
Status: accepted 2026-11-07
Concern: A user updates the skill dir (`npx skills add` again) but does not run `install` again. The harness config then keeps hook wiring from an older `install`, and nothing tells the user.
Decision: `install` writes the install stamp `<version>:<scope>` (for example `0.9.1:user`) into the config that it installs. Claude and Codex: the SessionStart hook command ends with `--installed <stamp>`. OpenCode and Pi: `install` replaces a placeholder in the adapter, and the adapter sends the stamp as `installed` in each payload. When SessionStart gets no stamp, or a stamp with a version that is not the version of the running skill, its banner gives the `install` command to run again, with `--scope user` for a user install. `doctor` reads the project install and the user install of each harness. Its `adapter installed` check passes when a detected harness has one of them, or any harness has one when `doctor` detects no harness. It gives a WARN with the same command for each install with the same condition. The shipped `scripts/hooks.json` template has no scope; its placeholder `MUTAGATE_VERSION` replaces all of the stamp.
Rationale: The stamp is in the same file as the hook wiring, so it is correct for each harness and each scope. It also stays correct when a committed portable install is cloned. SessionStart reads the stamp from its arguments or payload and reads no file.
Alternatives: A `scripts/.installed` file in the skill dir. One file cannot record more than one harness or scope, it is not in a clone, and `npx skills add` can replace or remove it. Rejected.
Consequences: Hooks from 0.9.0 and earlier have no stamp, so each session tells to run `install` again until the user does. Each version changes the SessionStart command, so Codex asks for trust again after `install`. A hook without a stamp, or with a stamp that has no scope, does not tell SessionStart the scope, so its notice says to add `--scope user` for a user install. `doctor` knows the scope from the file that it reads.
Related: ADR-0013 (hook commands and portable installs)
