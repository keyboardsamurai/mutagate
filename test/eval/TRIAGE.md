# Triage a mutagate eval sweep

You are pointed at one sweep directory, `test/.cache/eval/<sweepId>/`, produced by
`npm run eval`. Your job: find mutagate bugs in it and write them up as issues.
Every claim you make must cite a file and line inside the sweep. Do not re-run
agents. You may read `scripts/`, `docs/eval_suite.md` and the task under
`test/eval/tasks/<lang>/` to confirm a cause.

## Layout

Sweep dir:
- `report.md`: harness × scenario × task rows by language, `PASS 1/2 · 12.3m`
  cells, warnings grouped by id, the top 20 anomalies. Start here.
- `anomalies.json`: every run's anomalies merged.
- `<run>/`, one per run. Name `<harness>-<lang>-<scenario>-<n>`, or
  `<harness>-<lang>-<scenario>-greenfield-<n>`. The cell is the name without
  `-<n>`. A cell passes if any of its runs passes.

Run dir:
| File | Content |
|---|---|
| `meta.json` | harness, harnessVersion, model, lang, scenario, task, n, startedAt/endedAt and wallMs (agent only), exitCode, `ended` (`exit`, `idle` = driver done-detection, `killed` = run deadline), `session` (from the trace SessionStart). The deadline is 30 min from run start and covers copy, skill install, setup and the agent; `ended` null plus `error.log` naming a `failed (SIGKILL)` setup step means setup used it up. |
| `stdout.log`, `stderr.log` | the harness transcript. Claude: stream-json with `hook_response` events. Codex: `exec --json`. OpenCode: server message export, one part per line in time order (raw `run` output is `run.jsonl`, server log `serve.log`; the session database `opencode/data/opencode/opencode.db*` is deleted after the export). Pi: RPC events without streaming deltas. |
| `final.txt` | last assistant text, may be empty |
| `trace.jsonl` | mutagate's own trace (`MUTAGATE_TRACE=1`): one JSON event per line with `ts, harness, event, session, file, tool, decision, duration_ms, error`, plus `mutate` (true only for the async `--mutate` PostToolUse handler; absent in sweeps recorded before 2026-09-14's fixes); `Result` events carry `target, score, decision` (`pass`, `below`, `unscored`, `error`, `stale`, `killed`); `killed` from a clipped budget leaves the target pending |
| `runner-logs/` | per-target runner logs (JSON lines with exe, args, code, signal, output); `<key>.prev.log` is the run before |
| `recorded/` | raw hook payloads (`MUTAGATE_RECORD=1`) |
| `status.json` | `status --json` after the run, per target: file, tests, score, stale, blocks, result |
| `check.json`, `check.exit` | `check --json` joined to the hook session; exit 0 pass (including no mutants to test), 1 below/other unscored or no targets, 3 result/infrastructure error. `check`, `status`, the diff and the test command share a fixed 5 min grace after the agent ends; `SIGKILL` in an `.exit` file means the grace ran out. |
| `diff.patch` | the working tree against the baseline commit (`git add -N -A`, then `git diff <baseline>`), new files included; agent-written file content never enters `.git/objects` |
| `test-command.log`, `test-command.exit` | the task's `testCommand` run after the agent finished |
| `result.json` | checker verdict: `passed`, `skipped`, and `checks[]` with evidence strings |
| `anomalies.json` | `{kind: "check"\|"warning", id, message, run, evidence: [{file, line, text}]}` |
| `stage/`, `skill-diff.txt` | staged skill and paths of missing or changed installed files; adapters and `.node-path` are excluded. A nonempty diff fails `skill-modified`; missing is accepted for old dirs. |
| `repo` | symlink to the kept work repo at `~/.cache/mutagate-eval/<sweepId>/<run>-<16 random hex>` (sweep parent mode `0311`, repo mode `0700`; older dirs lack the suffix) (a real dir outside this tree, so Claude and Pi do not load mutagate's own `AGENTS.md`/`CLAUDE.md` from an ancestor, and it survives reboots). Older sweeps were moved there and their symlinks re-pointed. Read the repo through this link; `stale-deleted` resolves it with `realpath` and stays silent when it is dangling. |
| `error.log` | only when the suite itself crashed during the run |

A run dir with only `result.json` and `skipped` set was skipped by preflight
(wrong harness version, missing key or toolchain). Skips are not findings.

Secrets are scrubbed from every run dir and repo file before checks run: text
files get `<redacted>`, binary files get the same number of `x` bytes (length
unchanged); `.git`, `node_modules` and files over 5 MB are skipped. Ctrl-C
deletes `opencode.db` and scrubs every started run dir and repo, then exits 130. For a killed sweep,
`npm run eval -- --report <sweepDir>` re-renders `report.md` and the merged
`anomalies.json` from the runs' existing `result.json` and `anomalies.json`
without launching agents. It does not re-run the checker on the run dirs (call
`writeChecks(runDir, expected)` from `test/eval/checks.mjs` for that) and does
not rewrite evidence records.

## Check ids (hard; any failure fails the run)

| id | Fails when |
|---|---|
| `ended` | `meta.ended` is `killed` (timeout) or missing |
| `session-start` | no trace SessionStart with the run's harness label (hooks not wired, or wrong detection) |
| `registration` | a test file in `diff.patch` has no PostToolUse trace event naming it (hook missed the write or the tool is not mapped) |
| `targets-scored` | an `expected.json` target is not in `status.json` (unresolved) or has no numeric score (unscored, stale, error). Vacuous for greenfield. |
| `no-errors` | any trace event has `error` set, a status result is `error`, `check.exit` is 3, or a runner log shows a killed process. Superseded errors are left out and reported as warning `recovered-error` instead: a trace error with a target followed later by a `Result` for that target with a numeric score and no error, or a kill in `runner-logs/<targetKey>.log` whose target's final `status.json` result is scored and not an error. Only `status.json` results with status `error` count; `Result` trace reasons with decision `unscored` or `stale` are excluded. `status.json` error results, `check.exit` 3, hook and `Result` trace errors without a target and kills in multi-module targets' logs always count. Trace errors from CLI events whose message is an old usage error (the agent's own mistakes such as `run` on a bad path or `waive` without an id; engines after M5 fix pass no longer trace usage errors) never count; `worker` and other CLI errors do. |
| `gate` | `check.exit` is not 0 and not every `below` target in `status.json` has `blocks` >= `maxRounds` (2, per target). Also fails when no target is `below` (exit 1 from unscored or unresolved, exit 3). Trace Stop/SubagentStop/TaskCompleted blocks are not counted. |
| `skill-modified` | `skill-diff.txt` is nonempty: installed skill differs from the staged package; each path is evidence |
| `forced-order` | forced only: no `Stop block`, then later `Result pass`, then later `Stop allow`, in trace order |

## Warning ids (reported, never fail a run)

| id | Flags |
|---|---|
| `prod-changed` | files matching `prodFiles` but not `testFiles` changed beyond the prompt's `expectedProdEdits` (the agent weakened code to kill mutants?); new production files the agent added count too |
| `waiver` | waiver proposed (`waive`), waiver file edited, or the waiver-approval message (not its `Proposed: ${proposed}` template in dumped source) |
| `manual-run` | the agent ran `mutagate run --sync` or `run --target` by hand |
| `source-read` | the agent read mutagate source (`mutagate.mjs`, `mutagate-hook.cjs`, adapters, helpers) |
| `slow-hook` | a hook event over 1 s. Only PostToolUse events with trace `mutate: true` (the async `--mutate` handler, which settles 6 s by design) are exempt, whatever their duration. Sweeps recorded before the engine wrote `mutate` show every async PostToolUse here when re-checked; ignore those. |
| `stale-deleted` | messages in `stdout.log` or `check.json` about files missing from the repo: "target unresolved for <test>. Candidates", "mutagate: <target> results pending", "mutagate: <target> could not be scored: results pending" (and the pre-fix "infrastructure error: results pending" in older sweeps), and status lines "<target>: unscored\|error\|score N.NN (k/n), <status> stale". A target maps to a file through `status.json` `file`, then `expected.json` `targets[].file`, then the target id itself when it contains `/`. Files are looked up under the real path of `repo/`; no warning when it does not resolve. Captures containing `${` (message templates in dumped mutagate source) are skipped. |
| `unconfirmed-claim` | `final.txt` claims a pass (including "pass/exceed/above/meet the [0.80] threshold") while `check.exit` is not 0, or a score that `check`/`status` does not confirm. A number equal to the default threshold is not a claimed score. |
| `test-command-red` | the task test command is not green after the run |
| `tiny-mutants` | a scored target with fewer than 5 mutants; unscored results are excluded |
| `unscored-final` | a final `unscored` result has an `error` reason; evidence is `<target>: <reason>` |
| `async-missing` | the first mutagate `run` or `check` CLI call in `stdout.log` comes after the first non-user line naming a registered test file (a changed test file with a PostToolUse in the trace; `"role":"user"` lines are skipped because OpenCode and Pi echo the prompt), and no survivor report had reached the agent by then (no PostToolUse block in the trace, and no "survivors shown of", "could not be scored:" or pre-fix "infrastructure error:" text before the call). Also no warning when there were `Result`s before the first agent `run` or `check` CLI call (ignoring stale Results; a `decision: "cli"` trace event; in older run dirs the first event of a non-hook session) and all of them passed (nothing to deliver); with no `Result` at all it still fires. `status`, `waive` and `install` calls never count. |
| `recovered-error` | an error that `no-errors` left out because it was superseded: a trace error for a target followed later by a scored `Result` for that target, or a runner-log kill whose target's final `status.json` result is scored. Same evidence as the error. Typical cause: the agent's own compile error, fixed later. A mutagate bug only if the error text or the scored result is wrong. |

The checker is heuristic. Before filing, open the cited lines and confirm the
anomaly is real. A false positive is a suite bug (file against `test/eval/`).

## What is a mutagate bug

Is one (mutagate, its hooks or its adapters):
- hooks not firing, or a SessionStart/registration missing for a harness that
  was running (`session-start`, `registration`)
- wrong harness label, or the CLI not joining the hook session
- a target unresolved or unscored although the agent wrote a reasonable test
  for it (`targets-scored`); a test mapped to the wrong target
- the gate letting weak tests through: below threshold without a block
  (`gate`), a Stop allow while a touched target is below, or a first Stop
  allow on an `agent_caused` error result (the agent's red or non-compiling
  test must block once). Unresolved tests that create no obligation are a
  known design question, not a new bug (see the table below)
- async feedback lost: a result produced (trace `Result`) but never shown to
  the agent, or shown after the session went idle (`async-missing`,
  `manual-run` after silence)
- infrastructure errors from mutagate's runner invocation while the task's
  test command is green (`no-errors` without `test-command-red`)
- slow hooks (`slow-hook`), stale/unresolved messages for deleted files
  (`stale-deleted`), misleading hook or CLI text that sent the agent the wrong
  way (cite the message and the agent's reaction)

Is not:
- model laziness: thin tests, stopping early, skipping the integration test,
  not doing the sum endpoint
- a model ignoring or misreading clear feedback, or breaking rules the prompt
  set (running mutagate by hand when told not to is a model issue unless
  mutagate's own output told it to)
- provider errors (HTTP 4xx/5xx, stream errors, rate limits, "No endpoints
  found") in the transcript or `stderr.log`
- host flakes: toolchain missing, network, port collisions in TypeScript
  supertest tests (random 503/404), mutmut 3.0–3.5 segfaults on macOS (the
  pins are 3.8.0; a segfault with mutmut 3.6+ is a finding)
- Pi 0.73.1 not retrying OpenRouter mid-stream errors (harness bug, see below)
- an `ended: killed` run whose transcript shows long model steps and no
  mutagate wait (model latency), unless mutagate output sent the agent astray
- the agent's own compile or test failures, unless mutagate mishandles them
- a `slow-hook` on Stop that waited for an in-flight mutation run (gate wait,
  `gateWaitSec`): its `Result` lands just before the Stop line, often in the
  same ms
- Codex error items "--dangerously-bypass-hook-trust is enabled" at the top of
  `stdout.log`: the expected warning for the driver's flag
- suite bugs (checker false positives, driver done-detection): report them
  separately, marked as suite bugs

When in doubt, say which of the two and why, and give the evidence.

## Citing evidence

Cite as `<run>/<file>:<line>` with 1-based lines, and quote the relevant part,
for example `claude-java-forced-1/trace.jsonl:6` `{"event":"Stop","decision":"block",...}`.
Anomaly evidence uses the same `{file, line}`; line 0 means "absent" (the
checker found nothing to point at), and `status.json` is always line 1.
Correlate the trace with the transcript by timestamp (`ts` against the
transcript's own times), and the trace with runner logs by target name. Say
how many runs of the sweep show the same symptom.
