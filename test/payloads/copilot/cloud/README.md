# Copilot cloud coding agent payloads (spike S16)

Recorded 2026-11-10 in one GitHub Copilot cloud coding agent session (started with `gh agent-task create` on a probe branch, about 2 min, GitHub-hosted Linux runner, gh 2.103.3). The agent version is not recorded: the probe saved only the length of `COPILOT_AGENT_RUNTIME_VERSION`, and the session log names no version. The repo had three hook sources, each with one probe command per event: `.github/hooks/s16.json` (camelCase events), `.github/copilot/settings.json` (a top-level `hooks` key with the same entries, the form that Copilot CLI 1.0.107 added) and `.claude/settings.json` (Claude events). The probe saved stdin, the env names (no values, except `CI`, `COPILOT_CLI`, `GITHUB_ACTIONS`, `GITHUB_EVENT_NAME`, `GITHUB_JOB`, `GITHUB_WORKFLOW`, `RUNNER_ENVIRONMENT`, `RUNNER_OS`) and process ids. The task told the agent to run `ls`, add one file and commit; it did, through `bash`, `apply_patch` and its own tools.

A file holds the stdin of one call, unchanged except paths: `/repo` is the repo (`/home/runner/work/<repo>/<repo>`, which is `GITHUB_WORKSPACE`, the Git top and the hook cwd), `~` is the runner home (`/home/runner`). The repo owner login in the prompts is `<owner>`. The session id is the recorded agent task id. camelCase files come from `.github/hooks`; `<ClaudeEvent>-claude*.json` files come from `.claude/settings.json`. `schema-keys.json` lists the top-level keys per camelCase event and the `toolArgs` keys per `toolName` (`"string"`: the raw patch). `env.json` has the hook env names, the same in all 58 records, and the saved values. Audit: no token patterns (`github_pat_`, `gh?_`, `sk-`, `eyJ`, `Bearer`), emails, logins or local home paths.

Facts from the recordings:

- All three hook sources run in the cloud, for each event in this order: `.github/hooks`, `.claude/settings.json`, `.github/copilot/settings.json`. The `.github/hooks` and `.github/copilot/settings.json` payloads are byte-identical.
- Events that fired: `userPromptSubmitted` (before `sessionStart`), `sessionStart` (`source: "new"`), `preToolUse` and `postToolUse` (8 each), `agentStop` (`stopReason: "end_turn"`, `stop_hook_active: false`), `sessionEnd` (`reason: "complete"`). The Claude source got `SessionStart`, `PreToolUse`, `PostToolUse` and `Stop`. No tool failed and no subagent ran.
- The camelCase key sets are those of the local CLI (`../cli-native/`), with no `hook_event_name` and no `toolCallId`. `timestamp` is epoch ms on camelCase events and an ISO string on Claude events.
- `toolArgs` is JSON text (a string) for each tool, `bash` included. Only `apply_patch` sends the raw patch, and its headers have absolute paths. Locally `toolArgs` is an object, and patch paths are relative to `cwd`. Tool names: `bash`, `apply_patch`, `runtime-tools-secret_scanning`, `engine-tools-report_progress` (the agent commits and pushes through it).
- Claude-format payloads have `hook_event_name`, `session_id` and a top-level `timestamp`, as the local CLI calls of `../cli/`. `apply_patch` arrives as `tool_name: "Edit"` with the patch as a string `tool_input`.
- Hook env set only in the cloud (no local CLI hook or agent shell record has them): `COPILOT_AGENT_JOB_ID`, `COPILOT_AGENT_CALLBACK_URL`, `COPILOT_AGENT_RUNTIME_VERSION`, `COPILOT_AGENT_START_TIME_SEC`, `COPILOT_AGENT_SOURCE_ENVIRONMENT` and the other `COPILOT_AGENT_*` names except `COPILOT_AGENT_SESSION_ID`. Tokens in the hook env: `COPILOT_SDK_AUTH_TOKEN`, `GITHUB_VERIFICATION_TOKEN`. Also set, as in each local CLI hook call: `COPILOT_CLI=1`, `COPILOT_PROJECT_DIR`, `CLAUDE_PROJECT_DIR` and `AI_AGENT`. Also set: `COPILOT_AGENT_SESSION_ID` (36 characters; the probe saved no value, so its equality with `sessionId` is not recorded), which local agent shells have and local hook calls do not. Not set: `COPILOT_AGENT_PROMPT`, `GITHUB_COPILOT_API_TOKEN`, `COPILOT_HOOK_DEPTH`, `COPILOT_HOOK_DIR`, `COPILOT_CLI_BINARY_VERSION`, `COPILOT_CLI_PATH`.
