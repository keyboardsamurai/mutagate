# Copilot CLI payloads for native `.github/hooks` hooks

Recorded 2026-11-09 with GitHub Copilot CLI 1.0.107 (the Homebrew cask launcher is 1.0.104 and runs the cached 1.0.107 package; `copilot --version` and `COPILOT_CLI_BINARY_VERSION` say 1.0.107). Models: claude-sonnet-5.5 (tools `create`, `edit`, `bash`, `view`, `task`, `skill`), gpt-6-luna (tool `apply_patch`). macOS, local, trusted folder, Copilot sandbox off.

Each repo had `.github/hooks/probe.json` (`{"version":1,"hooks":{…}}`) with one `bash` command per event (`sessionStart`, `sessionEnd`, `userPromptSubmitted`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `agentStop`, `subagentStart`, `subagentStop`, `errorOccurred`), `timeoutSec` 30, no `matcher`. The command saved its stdin, env names and process ids. Sessions ran headless: `copilot -p <prompt> --output-format json --trust-folder --allow-all --no-ask-user --no-auto-update --model <model>`. A file holds the stdin of one call, unchanged except paths: `/repo` is the repo, `~` is the home directory. Session, agent and tool-call ids are the recorded random values. File names are `<event as Copilot sends it>-<case>.json`. `schema-keys.json` lists the top-level keys per event (union of all calls, subagent keys included) and the `toolArgs` keys per `toolName` (`"string"`: `toolArgs` is a string).

Facts from the recordings:

- Payloads are one line of camelCase JSON on stdin. No payload has `hook_event_name`: only the command knows the event.
- `timestamp` is a number (epoch ms) on every event. Through the Claude settings file (`../cli/`) it is an ISO string.
- `preToolUse`, `postToolUse` and `postToolUseFailure` carry `toolCallId`; pre and post of one call share it (`toolu_…` for Claude models; `custom_call_…` for `apply_patch` and `call_…` for `bash` with gpt-6-luna).
- `toolArgs` is an object for `create {path, file_text}`, `edit {path, old_str, new_str}`, `bash {command, description, mode?, initial_wait?, shellId?}`, `read_bash`, `view`, `task` and `skill`. `path` is absolute. For `apply_patch`, `toolArgs` is the raw patch text (a string, not JSON); patch paths are relative to `cwd`, and one call can add and update several files. `str_replace_editor` was not offered to either model, so it has no recording.
- `postToolUse` fires only on success and adds `toolResult {resultType: "success", textResultForLlm}`. A failed `edit`, `apply_patch` or `task` call fires only `postToolUseFailure`, with `error` (a string) and no `toolResult`.
- A `bash` command that runs longer than `initial_wait` (default 30 s) returns early: `postToolUse` fires at that time with a "still running" text, and the end comes through a later `read_bash` call (`postToolUse-bash-still-running.json`, `postToolUse-read-bash.json`).
- `agentStop` has `transcriptPath` (`~/.copilot/session-state/<sessionId>/events.jsonl`, under `COPILOT_HOME` when set), `stopReason` and snake_case `stop_hook_active`: false on the first stop, true on the stop after a block (`agentStop-forced.json`). The block reason arrives as a new `userPromptSubmitted` prompt (`userPromptSubmitted-block-reason.json`). `sessionEnd` fires once at the end, `reason: "complete"`.
- Subagent calls (`general-purpose`, `explore`, a custom `.github/agents/writer.agent.md`, and a `general-purpose` agent started by the custom one) add `agentId`, `agentType` and `parentAgentId`. Their tool hooks and their `agentStop` have `sessionId` = the subagent's own `agentId`, not the root session id. `parentAgentId` is the root `sessionId` at depth 1 and the parent subagent's `agentId` at depth 2 (`postToolUse-create-nested.json`). Root calls have no `agentId`.
- Every subagent fires its own `agentStop` (with `agentId`), then `subagentStop`; `general-purpose` does too. `subagentStart` and `subagentStop` carry the parent's session id: the root `sessionId` at depth 1, at depth 2 an internal id of the parent subagent, not its `agentId` (`subagentStart-nested.json`).
- `sessionStart` has `source` (`new`, or `resume` after `--resume`; the `sessionId` stays the same) and `initialPrompt`.
- Hook env set by Copilot: `COPILOT_CLI=1`, `COPILOT_CLI_BINARY_VERSION`, `COPILOT_CLI_PATH`, `COPILOT_CLI_RESOLVED_DIST_DIR`, `COPILOT_HOOK_DEPTH=1`, `COPILOT_HOOK_DIR` (`/repo/.github/hooks`), `COPILOT_PROJECT_DIR` and `CLAUDE_PROJECT_DIR` (the repo, also for native hooks). No `COPILOT_AGENT_SESSION_ID`. The agent's shell (the `bash` tool) has `COPILOT_AGENT_SESSION_ID` equal to the hook `sessionId` for the root agent, also after `--resume`; a subagent's shell has an internal id of that subagent: not its `agentId`, not the root `sessionId`.
- Copilot runs each command as `/bin/bash --norc --noprofile -c <bash>` in a new process group, child of the copilot process. Hooks of one event run one after another, never in parallel, and the agent waits for them.
