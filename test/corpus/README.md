This corpus tests the Kotlin fallback filter against actual PIT-generated mutants. It is intentionally more adversarial than a normal production run: PIT 1.21.0 enables its own `fkotlin` filter by default, which already removes many data-class methods.

`kotlin-unfiltered.xml` contains 121 mutants from Kotlin 2.1.21 and PIT 1.21.0, using `DEFAULTS,INLINE_CONSTS` and disabling `fkotlin` and `fstati`. In a disposable copy of the compiled fixture, `ExposeSynthetics.java` clears only the JVM `ACC_SYNTHETIC` flags on classes and methods. This makes PIT visit `$default` methods and `$WhenMappings` classes that its engine otherwise skips. The transformation does not change instructions, descriptors or line tables. Never apply it to application builds.

Reproduce the raw report with JDK 21, the pinned Gradle wrapper and verified PIT jars:

```sh
node test/corpus/generate.mjs /tmp/kotlin-corpus
```

Labels in `fixtures/kotlin-gradle/labeled-mutants.json` were assigned by inspecting source declarations and generated bytecode, without invoking the filter. Every row retains the original PIT fields and an explanation. The corpus test verifies all rows against the checked-in raw XML. Source and XML SHA-256 hashes bind the labels to their evidence. `coroutine-bytecode.txt` records the continuation dispatch examined during labeling.

Generated data-class methods are junk under the PRD's policy, while explicit overrides, getters, source arithmetic, and default literals are real. Coroutine labels, suspended-marker forwarding and debug locals are junk; source computations and explicit `resumeWith` calls are real. Some bytecode boilerplate remains eligible because the fallback cannot prove its origin safely from PIT fields alone.

Measured results: 121 mutants, 42 real, 79 junk; 48 flagged, precision 1.0, real drop rate 0, recall 0.6076. These figures cover this compiler and fixture only. They do not establish general Kotlin coverage or licensed Tier A behavior.
